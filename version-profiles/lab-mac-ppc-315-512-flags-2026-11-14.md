from the [2026-11-13 harness run](../live-runs/client-harness-2026-11-13/README.md#mac-powerpc-items-399).

## The probe

As on 2026-11-12 for 4.04r2 and 4.20r6:

- A protected GS1 weapon, on `playerenters || created`: `set probe1; setstring probe.x,1; set client.probec;`
  and a chat line, then `timeout=5`. On `timeout`: `set probe2; setstring probe.y,#v(timevar); setstring client.probey,#v(timevar);`
  and a chat line, then `timeout=5` again.
- A clientside GS1 level NPC on the start level does the same with `probe3`, `probe.z`, `client.probez`
  and, on its timer, `probe4` and `probe.w`.
- On the modern world, a GS2 weapon (`//#GS2`) as well: on `created`, `player.client.probe2c = 1`,
  `set("probe5")`, `setstring("probe.v", "1")`, `player.probe7 = 1` and a chat line; on its 5 s timer,
  `set("probe6")`, `setstring("probe.u", timevar2)` and `player.client.probe2t = timevar2`.

The `client.` flags are the positive control; the chat lines and timer values show that the scripts
ran. The account's `client.probe*` flags were cleared before the counted run, so the `created` sends
are not suppressed by flags the server already holds.

## Results

| Build | Scripts ran | id 18 (`PLI_FLAGSET`) sent | Plain and non-`client.` flags |
| --- | --- | --- | --- |
| Mac 3.153 (`G3D28015`) | yes: GS1 weapon and level NPC as source text; NPC chat on every timer tick | `client.probec`, `client.probez=1` on `created`, then `client.probey=<timevar>` on each tick (5 ticks in 150 s of a slowly emulated session) | **never sent** **[lab][cap]** |
| Mac 5.12 (`G3D15097`) | yes: the server translates the GS1 weapon and NPC to GS2 bytecode (ids 197, 140); the GS2 weapon runs as bytecode | `client.probec=1`, `client.probez=1`, `client.probe2c=1` on `created`, then `client.probey=…` and `client.probe2t=…` on each tick | **never sent as id 18** **[lab][cap]** |

- 5.12's GS2 has no `set` and no `setstring`: its console prints "Function set not found" and
  "Function setstring not found" for the GS2 weapon, and the script carries on **[lab]**. An
  assignment to a non-`client.` player variable (`player.probe7 = 1`) sends nothing **[cap]**.
- On 5.12 the plain and non-`client.` flags of the **translated GS1** probes do reach the server,
  but as `PLI_TRIGGERACTION` (38) `gr.flagset,probe1` / `gr.flagset,probe.x=1`. That is the lab
  server's GS1-to-GS2 translator (it turns a GS1 player flag into a `gr.flagset` trigger), not the
  client's own flag rule **[cap][srv]**.
- So all four Mac PowerPC builds (3.153, 4.04r2, 4.20r6, 5.12) send id 18 only for `client.`
  flags, on `created` and when a timer changes the value. 3.153 sends `client.probec` bare; 5.12
  sends `client.probec=1` **[cap]**.

## The 5.12 tileset

- With the Mac tokens known (5.12 Mac ranks as 5.12, above the 2.14 cut-off for large files), the
  server sends the stock 210 511-byte `pics1.png` (the tileset shipped in the Mac 4.04r2 bundle):
  id 102 in bz2 frames, and the 5.12 console counts "File download: pics1.png (size: 32000)…" up to
  "(size: 210511) done" **[lab][cap]**.
- The client had no cached tileset before that run, and the server log has no "File too large for
  client version" line **[lab]**.
- The level then draws: grass, bushes, trees, water and benches of the start level, with the A, S,
  1 and D HUD letters **[shot]**. This confirms the 2026-11-13 diagnosis: the black Mac 5.12 level
  came from the server refusing the tileset to an unknown token.
- Still missing in the lab world: `wbowi1.png`, `wbomb1.png`, `chest.png` and `bigmap.txt`
  ("not found"), so those HUD icons are blank **[lab]**.
- The "Connecting to Tiger Probe Modern…" box stays on screen after the warp although the session
  runs. The lab world's login scripts do not close it **[shot][inf]**.

## Notes on the method

- 3.153 runs only if the guest's lab DNS answers the listserver names in its licence. It shows the
  usual login screen (account, password, Start), then the server list, then Connect **[lab]**.
- An emulated 5 s script timer took about 20 to 50 s of wall time, so the tick counts are low.
  Each tick's value was still new, so each sent its own id 18 **[lab]**.
