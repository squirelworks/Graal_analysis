# Live runs of six eras under Wine, 2026-10-30

Six clients were run offline in a cloud container: 1st Graal (Sep 1998), 1.0 (10th Graal, Dec 1998), 1.1 (15th Graal, Jan 1999), 1.32 (Jan 2000), 1.41 rev1 (Nov 2000) and 2.00 (Feb 2001). Each was started in its own single-player or training mode, screenshotted, and timed while walking. No network: every client ran inside `unshare --net`. **[live]**

The screenshots, the helper scripts and the survey data are in the project folder under `graal-decompile/version-matrix/` (`shots/`, `tools/`, `survey.jsonl`). They are not in this repo.

## Setup notes for the old builds

These matter for anyone running a pre-2001 client in the lab (`../../tools/lab-setup.md`, and the live-trace setup used for 2.05):

* **Keyboard.** The 1998–1.41 clients read the keyboard through DelphiX `TDXInput`, which loads DirectInput. Under Wine 9.0 no key reaches them that way. With `WINEDLLOVERRIDES="dinput=d"` the DirectInput load fails, DelphiX falls back to the Windows keyboard state, and `xdotool keydown` works.
* **A window manager.** With bare Xvfb the game window never becomes active. With `openbox` running and the Wine virtual desktop on (`HKCU\Software\Wine\Explorer` `Desktop=Default`, `Desktops\Default=1024x768`), the window takes focus normally.
* **Idle-driven clients.** From NewMain 1.42 the frame runs from the idle handler. Under Wine it only advances while window messages arrive, so a screen can look frozen until the mouse moves. Keep posting small mouse moves during a measurement.
* **Missing files.** 2.00's archive holds only the exe. It runs from the 2.22 install folder once `objects.dat` (from any 1.x install) is copied in. The 1.21 InstallShield groups need their heads, swords and shields placed under `levels/` before the start window will open.
* **Reading positions.** The player position is a pair of doubles in tiles in every build tried. They were found by scanning for values that rise while Right (or Down) is held and fall while Left (or Up) is held, then polled every 2 ms with unbuffered reads of `/proc/<pid>/mem`. (A buffered reader returns stale bytes and makes the game look frozen.)

## Walking speed

| Build | Step | Interval | Speed | Notes |
|---|---|---|---|---|
| 1st Graal | 0.5 tile | 50 ms | 10.0 tiles/s | x from 12.5 to 14.0 in three steps |
| 1.0 (10th) | 0.5 | 50 | 10.0 | |
| 1.1 (15th) | 0.5 | 50 | 10.0 | After getting out of bed and bumping the furniture, x carried a 0.025 offset (26.925) and kept it while walking. 2.05's wall rule produces such offsets (`x + 0.525`-style probe points and 0.1 nudges), so a similar rule is likely; not read |
| 1.32 | 0.5 | 50 | 10.0 | Measured on y |
| 1.41 rev1 | 0.5 | 50 | 10.0 | Measured on y. A second copy of y moves in 0.25 steps (the view or the drawn position) |
| 2.05 rev2 | 0.5 | 50 | 10.0 | From the 2026-10-28 live trace (`walkBC`) |

So walking speed does not change from the first beta to 2.05, and the 2.17, 2.22 and 2.31 walking routines use the same half-tile step (`../../client-internals/decomp-findings-2026-10-25-m/01-walking-rule.md`).

2.00 was not timed: the training level opens with a scripted scroll that holds the player, and it did not finish within the run.
