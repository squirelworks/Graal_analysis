# GR-V1.05: a repaired server serves layers to native Linux 6.03r7

Date: 2026-11-21. Tags: **[lab]** for the bounded original-client run; **[srv]** for source ancestry.
Follow-up to [the earlier fuzz lab](gr-v105-fuzz-2026-11-19.md).
Evidence ID: `GR105-NATIVE603-POSITIVE` in [the evidence index](../docs/evidence-index.tsv).
Only derived results are published; captures, screenshots and raw logs remain private.

## Method and provenance

The client was the original **native Linux 6.03r7**, token `G3D0511C`, in a Debian VM.
The run manifest associates the existing GServer-v2 world binary with source `01bb0b3f`, a descendant of
[the reader repair, PR #118](https://github.com/squirelworks/seihai-gserver-v2/pull/118).
The source width guards were checked. Its working tree reported untracked build logs,
with no tracked source changes. This is reported deployment provenance, not an independently
reproduced source-to-binary build. This run did not rebuild the binary or rerun its tests. **[srv][lab]**

The login route retained the older login server; the fixed binary served the game world.
All traffic stayed on loopback within the VM's private network namespace. The client
authenticated, entered a hub, and was moved by injected chat warp commands through a
complete two-layer file, an explicit empty-hole variant, an RLE variant, and back to the hub.
These were generated fixtures, not vendor-original on-disk samples. The fixture's painted
tile was 332; the current generator's default 672 is not the oracle for this run.

The pre-run fixture decode found a complete hub link and post-board body in the two-layer
file. The live hub delivered 15 links. Returning to the hub used a chat warp, not walking
through one of those links, so this run does not establish link traversal.

## Delivered layers

Each observed `PLO_BOARDLAYER` (107) had five raw header bytes, followed by little-endian
16-bit tiles. The decoded header covered the full 64 by 64 board from cell (0, 0).
An independent decode of the private packet record reproduced all four histograms. **[lab]**

| Fixture | Layer | Painted cells | Empty cells sent as 65535 | Selected-cell check |
|---|---|---|---|---|
| two layers | 1 | 64 of tile 332 | 4032 | (28,28), (30,30), (35,35) are 332; (0,0) and (36,35) are empty |
| explicit empty hole | 1 | 63 of tile 332 | 4033 | (30,30) is empty; the painted endpoints remain 332 |
| RLE | 1 | 64 of tile 332 | 4032 | same selected values as the two-layer fixture |
| RLE | 2 | 16 of tile 333 | 4080 | (20,28) is 333; (0,0) and (30,30) are empty |

The upper-layer disk value 4095 reached the wire as the all-ones 16-bit empty value.
The explicit hole supplies a controlled difference: one painted cell becomes empty without
changing the rest of the patch. This is a served-file result, whereas the earlier lab's
successful 107 drawing came from injected packets.

## Drawing and session observations

The two-layer screenshot shows the painted patch over the grass base. The explicit-hole
screenshot shows the base through one cell in that patch. The retained RLE screenshot was
also inspected in this publication pass and shows both painted regions. The inspected
frames are not black-screen results. Client-alive markers continued through all visits,
the return to the hub and the final frame. **[lab]**

The plan's initial wait for packet 9 missed an earlier packet and timed out after 60 seconds;
the plan then continued. This timeout is retained as a harness qualification, not silently
counted as a successful wait. There was no independent bomb or gameplay canary.
