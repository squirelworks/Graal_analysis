.SH NAME
tiletypes \- which tile ids block, and which are water
.SH SYNOPSIS
server/include/tiletypes.h
.br
share/tiledefs.txt
.SH DESCRIPTION
The client does not inspect the tileset image.
A board stores a tile
.B id
(0..4095).
Collision is a second table, indexed by that id.
.PP
.I tiletypes.h
holds
.I static const unsigned char tiletypes[4096]
copied from the standard Graal tileset, plus
.IR tiletypes_len " = 4096."
.I share/tiledefs.txt
is the same 4096 bytes written in decimal, row-major, 128 values
per line (the width of
.BR pics1.png ).
.SS The only tests this client runs
From
.I TLevel.cpp :
.PP
.RS
.nf
bool TLevel::isOnWall(double pX, double pY)
{
    if (pX < 0 || pY < 0 || pX > 63 || pY > 63) return true;
    return tiletypes[levelTiles[int(round(pY)) * 64 + int(round(pX))]] >= 20;
}

bool TLevel::isOnWater(double pX, double pY)
{
    return (tiletypes[levelTiles[(int)pY * 64 + (int)pX]] == 11);
}
.fi
.RE
.PP
So, for this client:
.IP \(bu 2
.B wall
if the type byte is
.B >= 20
(also if the foot is outside the 64x64 board)
.IP \(bu 2
.B water
if the type byte is
.B == 11
.IP \(bu 2
.B walkable
otherwise, including types the official client treats as special
.PP
Outside the board,
.B isOnWall
is true.
.B isOnWater
does not range-check; a bad coordinate reads off
.IR levelTiles .

.SS Not the Graal.exe body mask
A decompile note shipped as
.I attachments/tiledef.txt
describes Graal.exe v2.05.
That file is a different grid: a 0/1 body-block mask for tileset
types 1 and 2 (1725 blocked, 2371 walkable).
Stock selection there is
.I pics1.png,,0
and type 0 walks only if the id is in two sorted lists that the
decompile did not emit.
.B setshape2
in that client blocks the body when the shape-tile type is greater
than 19, which matches
.B >= 20
here.
Throw handling there does
.B not
stop on type 0x14 (20).
This SDL client has no such split: 20, 21, and 22 are all walls.
.SS Id to picture
On
.B pics1.png
(2048x512, palette, 128 by 32 tiles of 16 px):
.PP
.RS
.nf
col = id % 128
row = id / 128
pixel = (col * 16, row * 16)
.fi
.RE
.PP
The first data line of
.I tiledefs.txt
is ids 0..127.
It starts
.I 0,0,20,20,...
so the top-left two tiles walk and the next two are walls.
The 2x2 Bush stamp in
.BR tileobjects (7)
writes ids 2, 3, 18, and 19, which this table marks 20, 20, 22, 22.
The stamp file itself has no collision column.
