# GR-V1.05: introduction build and on-disk shape (5.00r7)

Date: 2026-11-16

Static reads of the stock Windows engines only. Tags: **[bin]** · **[inf]**.

## Which build adds the file magic

| Build | `GR-V1.04` | `GR-V1.05` | Notes |
|---|---|---|---|
| Windows 4.20r8 `GraalEngine.dll` | yes | **no** | `tilelayers` already appears as a level child name; board layers exist on the wire (id 107). The **file** magic is not present. **[bin]** |
| Windows 5.00r7 `GraalEngine.dll` | yes | **yes** | First held Windows engine whose string table and level I/O include `GR-V1.05`. Later 5.x/6.x engines keep it. **[bin]** |

So on the held ladder, **`GR-V1.05` is new with 5.00r7**. It is absent through stock 4.20r8. No earlier 5.00 revision was held for this pass, so the gap between those two link stamps is not narrowed further. **[bin][inf]**

This matches the short statements in [`v4x-clients.md`](../protocol/v4x-clients.md#file-formats) (no `1.05` yet) and [`v5x-clients.md`](../protocol/v5x-clients.md#file-formats) (`1.05` new in 5.x).

## Shape over `GR-V1.04`

`GR-V1.05` is the multi-layer file form of the packed board family:

1. eight-byte magic `GR-V1.05`
2. one **GCHAR** layer count (`byte − 32`)
3. **one** 64×64 board **per layer**, **13-bit** codes (same family as `GR-V1.02`+)
4. then the usual post-board body, including an optional `HEIGHTS`…`HEIGHTSEND` block as in `GR-V1.04`

There is **no** pad between the layer-count byte and the first board in the stock reader/writer path. **[bin]**

## Writer rule (5.00r7)

When saving a binary level, the stock engine picks the magic from the live level state:

| Condition | Magic written |
|---|---|
| Live tile-layer count **greater than 1** | `GR-V1.05`, then GCHAR(count), then one board per layer |
| Else if a height map is present | `GR-V1.04` |
| Else | `GR-V1.03` |

On the `1.05` path the written layer count is clamped to at most **223** (`0xDF`) before it is stored as a GCHAR. **[bin]**
