# `.nw` layer and tileset extensions on stock 5.00r7

Date: 2026-11-16. Tags: **[bin]** for the stock Windows 5.00r7 engine text-level loader; **[inf]** where 6.x cleartext is incomplete.

Leads-only confirm against a third-party editor claim. No third-party code. No paths or addresses.

## Questions

1. Does stock read a trailing layer index on `LINK` / `CHEST` / `BADDY` / `SIGN` / `NPC`?
2. Does stock read a LINK destination layer?
3. Does stock read `TILESET` / `TILESETIMAGE` lines?
4. Which `BOARD` layers beyond 0 and 1 are honoured?

## Keyword table (5.00r7)

The engine's text-level keyword cluster includes the classic magics and record names (`GLEVNW01`, `BOARD`, `LINK`, `CHEST`, `SIGN`/`SIGNEND`, `NPC`/`NPCEND`, `BADDY`/`BADDYEND`, `HEIGHTS`/`HEIGHTSEND`, `GR-V1.04`, `GR-V1.05`, …). It does **not** contain `TILESET` or `TILESETIMAGE` anywhere in the scanned image. The same absences hold on a 5.12 engine string dump. **[bin]**

A staged 6.03r7 Windows image still names the binary multi-layer / heights path (`GR-V1.0*`, `HEIGHTS`, `tilelayers`) but does **not** expose the classic `.nw` keyword table in cleartext, and still has **no** `TILESET` / `TILESETIMAGE` literals. Full 6.03r7 keyword strcmp on a cleaner extract remains open. **[bin][inf]**

## Field counts after the keyword (5.00r7)

| Keyword | Min fields | Fields used | Trailing object-layer index? |
| --- | --- | --- | --- |
| `BOARD` | **5** | `x y w layer tilesdata` | Layer is the **4th** field and **is used** |
| `LINK` | **5** (opt 6–7) | `dest x y w h` + optional arrival-x / arrival-y strings | **No** 8th field / dest-layer |
| `CHEST` | **4** | `x y item sign` | **No** |
| `SIGN` | **2** | `x y` then body → `SIGNEND` | **No** |
| `NPC` | **3** | `image x y` then body → `NPCEND` (`-` = no image) | **No** |
| `BADDY` | **3** | `x y type` then verses → `BADDYEND` | **No** |

`LINK` optionals: if at least six fields, field 5 is the arrival-x string (token `-1` means keep the player's x); if at least seven, field 6 is arrival-y (same for y). That is the classic newx/newy pair — **not** a destination layer index. **[bin]**

## `BOARD` layers above 1

On 5.00r7 the layer token indexes the level's `tilelayers` array: the engine grows that array when needed, rejects a negative / out-of-range index, and writes the 12-bit tile run into that layer's 64×64 board. So **any non-negative layer index the array can hold is honoured** — not limited to 0/1. Layer 0 is the base board; higher indices are real overlay boards on disk, matching the engine's `tilelayers` / wire board-layer world. **[bin]**

This supersedes older server-era wording that a layer index was parsed and unused, for **5.00r7 clients**. **[bin]**

## Verdicts

| Question | Stock answer (5.00r7) |
| --- | --- |
| Trailing layer on LINK/CHEST/BADDY/SIGN/NPC | **No** — fixed classic field counts only |
| LINK destination layer | **No** — only optional newx/newy |
| `TILESET` / `TILESETIMAGE` | **No** literals on 5.00r7 / 5.12 / staged 6.03r7 |
| `BOARD` layers > 1 | **Yes** — layer field indexes `tilelayers[]` |

Editor implication: do **not** emit third-party-only `TILESET` lines or trailing object-layer / LINK dest-layer fields for stock clients. Emitting `BOARD … layer≥2 …` is fine for 5.00r7+ engines that own `tilelayers`.
