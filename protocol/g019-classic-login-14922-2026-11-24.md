# Public listserver: classic login on port 14922 (2026-11-24)

Derived note. One owner-approved list-only check (Asia/Tokyo afternoon) against `<list-host-reborn>` on port **14922**. Manual pace, one session, no second port, no game-server login, no chat, no warp, no retries. Login-frame bytes, credentials and the host name stay private. Partial close of App. E#403 / gap **G019**: whether today's public **14922** answers a classic list login.

## Login sent

One plain zlib frame (default level, wire header `78 9C`), classic shape B from [`listserver-login-type-matrix-2026-10-25.md`](listserver-login-type-matrix-2026-10-25.md) / [`listserver.md`](listserver.md) (2.17-style):

- id **0**: `newmain` + LF
- id **1**: account + password (GSTRINGs) + LF

Wire length was **35** bytes (**25** clear). No gen-5 id 7, no cipher, no compression-type byte.

## Result

| step | outcome |
|---|---|
| TCP connect to **14922** | accepted |
| S→C after login | **two** plain-zlib frames, **416** bytes on the wire, ~5.9 s read wait |
| Frame 1 | id **0** list, **4** rows |
| Frame 2 | ids **2**, **3**, **5**, **6** (status / site / upgrade / one extra id) |
| refuse / reset / rate-limit | **absent** |

So today's public **14922** **answers** a classic shape-B login with a legacy-style plain-zlib list plus a status frame. That **overturns** the 2026-10-25 matrix, where every classic login on 14922 stayed silent for the 5 s read timeout ([`listserver-login-type-matrix-2026-10-25.md`](listserver-login-type-matrix-2026-10-25.md)).

Row count **4** is that afternoon's list size, not a protocol constant. Id **6** on the status frame matches the extra id seen on gen-5 public replies the same day ([`g3d30123-public-listserver-2026-11-24.md`](g3d30123-public-listserver-2026-11-24.md)); its layout was not traced here.

## What this settles

- Public **14922** is reachable and, on 2026-11-24, speaks the classic (pre-gen-5) list reply to a shape-B login.
- The E#403 live claim that "public 14922 accepts a classic login and never answers it" no longer holds for today's service.
- The 2001-era tools' split (`clientPort` 14922 / `clientPortOld` 14923) remains a reading of old config, not a proof of what 2001 answered on each port.

## What this does not show

- A stock 2.17.1 (or any other pristine classic client) was not captured; only the documented classic wire shape.
- Whether the 2001 service answered classic logins on 14922 (historical behaviour still open).
- Port **14923** classic behaviour was re-checked later the same day (see `g020-classic-login-14923-2026-11-24.md`).
- No game-server login followed the list.
