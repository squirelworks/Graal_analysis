# Packet captures — 2026-10-04 sessions

Source: `server packeting 2026-10-04 *.pcapng` (12 files).

## Framing
All game traffic is **2-byte big-endian length + zlib payload**.
After the login frame, some servers (port 14801) switch to an encrypted stream (zlib no longer decompresses). Others (14842, 14912) stay clear zlib.

## Login (cleartext, first client frame)

| Session | Port | Version ID |
|---------|------|------------|
| 01 | 14801 | `GNW28015` |
| 03 | 14842 | `GNW22122` |
| 04 | 14801 | `GNW03014` |
| 11 | 14912 | `GNW07080` |

Version IDs observed: `GNW28015`, `GNW22122`, `GNW03014`, `GNW07080`, `GNW30123`.

Shape: optional prefix bytes, then `GNW#####`, then length-biased account and password fields. Credentials redacted.

## Short client packets (clear sessions 03 / 11)
Repeated 4–6 byte frames, newline-terminated. Examples:

```
"1-\n   "1%\n   "0f\n   "1o\n
"/[\n   "/ZA\n   "/AY\n   "0[14\n
```

One longer example includes a GANI name:

```
"*$walk/I\x96\n
```

These are the client→server updates (movement / action). Encoding is character-based (packet type + offset coords), not the provisional f32 layout. Exact field split still needs a side-by-side with the open packet-type tables.

## Server packets (clear)
First bytes seen: `9`, `O`, `M`, `>`, `J`, `'`, `)`.
Content includes file pushes (`sword1.png`, `head25.png`, `walk.gani`, `steps.wav`) and short updates (`Jm?z.\n` style).

## Implications for Seihai
- Login can drop the provisional `PacketId::Login` blob. Use length-prefixed zlib and the `GNW#####$user)pass!!\n` shape.
- Movement is **not** raw f32. It is a short character-encoded frame. Keep `write_classic` / `write_precise` as property helpers; do not send them as the movement packet.
- Version string should be a `GNW*` id, not `"2.31"`.

## Still open
