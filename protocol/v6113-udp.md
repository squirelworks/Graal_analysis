# UDP ports in a full 6.113 capture

Date: 2026-11-07. One owner-supplied capture, 15236 frames, 112.112 seconds. Nothing was run from this repo. The capture stays out of the repository. Tags: **[cap]**.

`protocol/v6113-list-capture.md` is a different file from the same day (1086 frames, TCP only). This file is the whole interface. Hosts, addresses, accounts and session bytes are left out. The client is the only host that sends a TCP SYN.

## What this capture shows

The client opens three TCP ports: 80 (1 session), 443 (45 SYNs, 43 answered) and 14900 (4 SYNs to three remotes). One 14900 SYN is unanswered. The three completed 14900 sessions each start with the eight-byte token `GNP1905C`. Their TCP payload sizes are:

| Remote | Client packets | Client payload bytes | Remote packets | Remote payload bytes |
| --- | ---: | ---: | ---: | ---: |
| unanswered | 1 | 0 | 0 | 0 |
| first remote, first session | 28 | 1754 | 29 | 3767 |
| first remote, second session | 36 | 2113 | 39 | 10051 |
| second remote | 1295 | 48430 | 2095 | 3610620 |

The server's first segment on those three sessions is 290, 288 and 279 bytes, and it does not start with that token.

UDP was counted with tshark, keeping datagrams and dropping six ICMP messages that only quote a NAT-PMP request. That leaves 2952 datagrams. 2811 belong to the client. None of those 2811 is to or from a remote that also has TCP 14900 in this file. The UDP 443 remote is a separate host from every TCP session the client opens.

Across the whole file, the only UDP port numbers that also appear on TCP are 443 and 22000. No UDP port sits one below a TCP port. UDP 14901, beside TCP 14900, has no datagram.
