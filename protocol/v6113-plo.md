## Incoming registration

`setindatahandlers` reads a flat list of byte pairs. The first byte is the wire id. The second byte is the handler:

| Handler byte | What is stored for that wire id |
| --- | --- |
| 255 | The slot is cleared. A cleared slot is ignored |
| 254 | The slot holds the script sentinel. The native caller does not call a function for that sentinel |
| 253 | The wire id is saved on the connection, and the slot is cleared |
| 252 | The wire id is saved in a second connection field, and the slot points at one fixed function |
| 0 to 94 | The slot points at that index in a table of 95 native functions. Index 90 is empty |
| 95 and above, apart from the four values above | The pair is skipped |

`clearindatahandlers` zeros all 256 slots. Until a script sends pairs, no wire id has a handler. **[bin]**

The native functions are also exposed as script methods. The names present include `tclient_setplayerprops`, `tclient_setotherplayerprops`, `tclient_setnpcprops`, `tclient_setbaddyprops`, `tclient_settoallmsg` and `tclient_setfilekey`, plus the rest of the `tclient_*` set. Which table index belongs to which name was not joined in this read. **[bin]**
