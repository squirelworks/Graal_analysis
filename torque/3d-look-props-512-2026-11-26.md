# 5.12 cross-view of player look props: 2D ⇄ 3D (2026-11-26)

Lab: a real 5.12 (3D) and a 5.24r4 (2D) client in one world on our own
gserver on loopback (never a third-party server). Question (T3D-069): do a
player's 2D look props (head, body, colours, gani, chat, nickname) show on
the *other* client's view, and how? Behaviour only; screenshots stay in the
lab kit. **[lab][cap]** — partial (see "Not completed").

## The cross-view is asymmetric

- **The 3D player, seen on the 2D client → full 2D sprite + name tag.** On
  the 2D screen the 3D player renders as a normal 2D player sprite — head,
  body, gani, sword/shield (the account 2D look) — **with a name tag** over it
  (the account/nick, e.g. `pc:2`). So the 3D player's whole 2D look and name
  show on the 2D side.
- **The 2D player, seen on the 3D client → the 3D model, not the 2D look.**
  On the 3D screen the other player renders as the **3D model** (the
  `tgeplayershape` cube / `G2DPlayer`), **not** the 2D head/body sprite. The
  2D head / body / colours / gani images do **not** show in 3D; nickname and
  chat are carried as text per the server's player rows.

So the two directions differ: the 3D player's 2D look shows in full on the 2D
side, but the 2D player's 2D look does **not** reach the 3D side — the 3D
engine substitutes a player model.

## Live changes from the 3D client don't propagate

Changing 2D-look props from the 3D client (head→head1, body→body1, a chat
line, nick — all four fired, logged "3D set …") left the **2D** client's view
of that player unchanged: the sprite kept the account-default head/body and
the `pc:2` name tag, with no chat bubble. So a 2D-look prop changed
client-side in 3D does **not** propagate to the other screen; the cross-view
shows the account-default look.

## Not completed

## Conclusion (partial)

The direction and rendering are clear: a 3D player appears on a 2D client as
their full 2D sprite with a name tag, while a 2D player appears on a 3D
client as a 3D model (no 2D head/body), and a 3D-side 2D-look change does not
propagate. The fine-grained per-prop matrix in the 2D→3D direction is still
open pending a stable 2D client.
