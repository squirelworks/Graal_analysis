# The 2D GUI layers over the 3D view, and GS2 GUIs draw in 3D (T3D-058, Linux 4.20r6)

Date: 2026-11-25. Loopback lab of the Linux 4.20r6 client (5.12-class, protocol 24) against our own 3D lab server, GS2 drawn via a client-side `weapon3d` script (runs `gui420-a`; no movement input), plus the GS2 `-listscriptfunctions` dumps for 4.04r2/4.20r8/5.00r7/5.12. Linux 4.20r6 is 3D-equal to 4.20r8 ([T3D-004](3d-engines-5007-512-and-403-411-2026-11-25.md)). Board row: [T3D-058](3d-capability-board.tsv). Contrast with [T3D-060](3d-2d-level-packets-420r6-2026-11-25.md) (2D level content inert in 3D).

## Headline

**Yes — a GS2 GUI draws over the 3D view.** A client-side `weapon3d` script calling `showtext` and `showimg` put a live text label and an image **on top of** the 3D scene. The 3D viewport is **not** exclusive: unlike 2D *level* content (swallowed in 3D, [T3D-060](3d-2d-level-packets-420r6-2026-11-25.md)), the 2D *GUI/HUD* layer renders above the 3D view.

## GUI classes and draw functions **[bin]**

From the GS2 dumps for 4.04r2, 4.20r8, 5.00r7 and 5.12:

| GUI item | 4.04r2 | 4.20r8 | 5.00r7 | 5.12 | what it is |
| --- | --- | --- | --- | --- | --- |
| `GuiControl` | Y | Y | Y | Y | the base GUI control |
| `GuiGraal3DCtrl (GuiControl)` | Y | Y | Y | Y | the 3D viewport — itself a GuiControl |
| `GuiShowImgCtrl (GuiControl)` | Y | Y | Y | Y | the showimg/image overlay control |
| `GuiBitmapCtrl` | Y | Y | Y | Y | a bitmap GUI control |
| `showimg(int, str, float, float) → object` | Y | Y | Y | Y | image overlay (layer, image, x, y) |
| `showtext(int, float, float, str, str, str) → object` | Y | Y | Y | Y | text overlay (layer, x, y, font, style, text) |
| `drawover`, `showani`, `showpoly` | Y | Y | Y | Y | other overlay draw calls |

- **`GraalControl3D` / `GUIContainer3D` (as the board named them) do not exist** in any dump. The real 3D-view class is **`GuiGraal3DCtrl`**, a subclass of `GuiControl` — the 3D view is one GUI control sitting in the ordinary GUI hierarchy.
- **The 2D GUI layer is the shared 2D GUI the 2D client uses** — `GuiControl`, `GuiShowImgCtrl`, `GuiBitmapCtrl`, `showimg`/`showtext` are the standard Graal 2D GUI, identical on 4.04r2 and the 5.x family. It is not a 3D-specific GUI. Because the 3D viewport is itself a `GuiControl`, overlays from `showimg`/`showtext` are its peers in the GUI tree and layer over it.
- `GuiShowImgCtrl` carries 3D-aware fields (`attachnode`, `attachoffset`, `attachtoowner`, an `emitter`), so an overlay can be pinned to a 3D node — not needed to draw over the view.

## Lab: a GS2 GUI draw over the 3D scene **[lab]**

A `weapon3d` GS2 bytecode script (delivered over the 3D text channel, runs client-side, [T3D-018](3d-client-events-420r6-2026-11-25.md)) on `onCreated` did `showtext(200, 120, 120, "Arial", "cb", "GUI3D OVERLAY")` (red, counter updated every 2 s) and `showimg(201, "guimark.png", 350, 250)` with a pre-placed marker image (on disk with its extension, [T3D-077](3d-texture-formats-420r6-2026-11-25.md)).

Result (screenshot at 45 s): the 3D scene drew normally (red GameObject cube, sky, ground); the **red text `GUI3D 15`** was drawn over the scene (the counter confirms live `onTimeout` updates); the **yellow marker** was drawn over the scene, on top of the cube (so overlay z-order is above the 3D view). The client fetched `arialbd.ttf` (the font `showtext` needs) and checked `guimark.png` on disk — both triggered by the calls. No GUI/draw error in the console.

**Contrast with [T3D-060](3d-2d-level-packets-420r6-2026-11-25.md):** 2D *level* content (board, NPCs, signs) is inert in a 3D session; the 2D *GUI/HUD* layer draws over the 3D view. Different layers: the 2D level-world renderer is off while the 3D viewport owns the scene, but the GUI compositor still paints GUI controls (including overlays) on top of whatever viewport is active.

## For a server

- A client-side GS2 script can build a HUD/GUI over the 3D view with the ordinary 2D GUI calls (`showimg`, `showtext`, `GuiShowImgCtrl`, …) — the same ones a 2D client uses; there is no separate 3D GUI API. Overlays render above the 3D viewport (`GuiGraal3DCtrl`).
- A HUD overlay can optionally be pinned to a 3D node via `GuiShowImgCtrl`'s `attachnode`/`attachoffset`/`attachtoowner`.
- This is the GUI layer only; 2D *level* content remains inert in 3D ([T3D-060](3d-2d-level-packets-420r6-2026-11-25.md)).
