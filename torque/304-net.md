# Graal TCP beside stock Torque in Linux 3.04

Date: 2026-11-07. Static read of the Linux `graalexe` 3.04 decompile. Nothing was run. Tags as in [README.md](README.md).

The game's own network code is `graal/client.cpp`, `graal/graalconnection.cpp`, `graal/serverlist.cpp`, `graal/playerlist.cpp` and `graal/serverplayer.cpp`. Torque's UDP net is compiled in beside it and is not modified by those files. **[bin]**

## Beside Torque

Torque's net sources in this binary include `sim/netConnection.cc`, `sim/netGhost.cc`, `sim/netDownload.cc`, `sim/netStringTable.cc`, `game/gameConnection.cc`, `game/gameConnectionEvents.cc`, `game/aiConnection.cc` and `game/net/net.cc`. No function that names one of those files also names a `graal/` file. The console class `GameConnection` still has the stock methods (`chaseCam`, `activateGhosting`, `resetGhosting`, `playDemo`, `setMissionCRC`, and the rest of that table). `NetConnection` still has `connect`, `getPing`, `getPacketLoss` and `getAddress`. The connect log lines are the stock `Sending Connect challenge Request` and `Sending Connect Request`. This binary has no `Graal3D` game string and no `BigData` event name. **[bin]**

`TGraalConnection` is a C++ type with no base class in the type info. It is not registered as a Torque console class, and it is not a `NetConnection`. The object that actually carries the bytes is allocated from `graalconnection.cpp` and then opened with the host and port strings the caller passed. A length check in that unit treats a buffer longer than 65535 as too big. **[bin]**

## The game connection

`client.cpp` starts from the name `Offline` and an all-zero IPv4 address, and from the text `Your messages are ignored.` The live session is labelled `game server`. It logs `Connecting to the game server...`, builds a `TGraalConnection`, and on success logs `Done.` **[bin]**

The login message is id 5. The token is appended one character at a time: `G`, `3`, `D`, `0`, `3`, `0`, `1`, `4`, which is the 3.04 game-server token in [protocol/v3x-clients.md](../protocol/v3x-clients.md), then the account and password. The next send is id 37, the language preference, whose default literal is `English`. The id set the receive switch handles is the 3.04 column of that same note. **[bin]**

File progress is logged as `File download: %s not found`, `File download: %s (size: %d)...` and `File download: %s (size: %d) done`. A `.gmap` name is special-cased on the way in. An explosion message plays `thunder.wav` or `bomb.wav` (the sound unit in [304-audio-ui.md](304-audio-ui.md)) and then spawns the burst. Other cues named here are `item.wav` and `extra.wav`. The word `clientside` and the word `action` are sent into script from this unit. **[bin]**

The `$pref::Graal::noudp` flag skips the UDP send path. A failed send logs `UDP send error: %d`. That path is Graal's own channel in `client.cpp`, separate from Torque `GameConnection`. Screenshots requested from this unit go under the folder name `screenshots` and again call Torque `screenShot`. **[bin]**

`serverplayer.cpp` is the other people, type `TServerPlayer` ([304-draw.md](304-draw.md)). A new one starts as `English`, `sword1.png` and `shield1.png`, and falls back through `sword2.png` to `sword4.png`, `shield2.png`, `shield3.png` and `head0.png`. The idle animation it names is `bomy_idle`. It recognises a body that starts with `Mass message:` or `Guild message:`. A profile is a file under `profiles` ending in `.txt`, with a `---` separator in the text. **[bin]**

## The server list and the player list

`serverlist.cpp` labels its session `server lister`. Opening it runs `Canvas.setContent(ServerListGui)`. A drop logs `Disconnected from serverlister`, shows `MessageBoxOK` with `Disconnected`, and returns to `MainMenuGui` when no game connection is open. Category buttons are `ListButtonGold`, `ListButton3D`, `ListButtonClassic` and `ListButtonHosted`. The detail fields are `ServerLanguage`, `ServerGraalVersion`, `ServerDescription` and `ServerHomepage`. Rows are added with `ServerList.addRow`. **[bin]**

Choosing a row requires more than seven fields. Field 0 is the name, field 6 the host and field 7 the port. When the second character of the name is a space, the first two characters are removed (the category prefix). The nickname preference is copied, tiles are loaded, `Canvas.setContent(AdventureGui)` runs, and `client.cpp` opens the game connection. `connectToSelectedServer` is this path. `openServerList` is the list path. `serverDirectConnect` passes the script string straight in. **[bin]**

`playerlist.cpp` reads `ignoredaccounts.txt`, `buddyaccounts.txt` and `mutedaccounts.txt`. List icons use the prefix `plisticon` and `.png`, and the baddy prefix `bomy_`. A private message opens `PrivateMessageGui`. A received message sets the edit box to `GuiMLTextProfile`, takes away first-responder, and sets the button from `$language::Reply`. Sending sets `GuiMLTextEditProfile`, focuses the box, reads `PrivateMessageEdit.getText()`, sets the button from `$language::Send`, and pops the dialog. **[bin]**

The profile dialog is `PlayerProfileGui`. Text fields are filled from the profile, and the gender words are `male` and `female`. The stat rows are `kills`, `deaths`, `maxpower`, `rating`, `alignment`, `gelat` (the label is `Gralat:`), `swordpower` and `spin`, with the labels `Kills:`, `Deaths:`, `Maxpower:`, `Rating:`, `Alignment:`, `Swordpower:` and `Spin:`. `updatePlayerProfile` (twelve arguments on the control) hands those fields to this unit. The load-level dialog writes `LoadLevelFilenameField`, `LoadLevelXField` and `LoadLevelYField`. **[bin]**
