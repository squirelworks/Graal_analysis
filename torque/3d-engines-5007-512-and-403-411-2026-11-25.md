# 3D engines compared: 5.00r7 vs 5.12, 4.03r3 / 4.11 vs 4.04r2, and Linux/Mac vs Windows (T3D-005, T3D-003, T3D-004)

> **Count correction (T3D-004 pass, same day):** the Windows class counts below came from a scan of class-name stores that missed the `fx` family, which registers through a different code shape. The complete sets are **117** (4.03r3 = 4.04r2, not 108), **32** (4.11, not 30) and **28** (4.20r8 = 5.00r7 = 5.12, not 27), and the 4.0x datablock family is **29** (fxLightData included). The datablock-to-GameObject switch is also earlier than 4.11: Linux and Mac 4.10r2 already have it. See [Linux and Mac](#t3d-004-linux-and-mac-against-their-windows-twins).

Date: 2026-11-25. Static only: class registrations, the protocol constant used by the connect-reject code, string sets, and the `-listscriptfunctions` dumps ([G066](../client-internals/script-function-lists-focus-2026-11-25.md)). Nothing was run. Board rows: [T3D-005 and T3D-003](3d-capability-board.tsv). **[bin]**

## T3D-005: 5.00r7 is 3D-equal to 5.12

| | 5.00r7 | 5.12 | 4.20r8 |
| --- | --- | --- | --- |
| Protocol constant | 24 (separate too-old, too-new and wrong-game rejects) | 24, same reject code | 24 |
| Registered classes | 27 | 27, same names | 27, same names |
| GS2 3D object types | 37 owners | the same 37 | 37 (TFlashInstance instead of MovieClip) |
| GS2 functions | 706 | 713 | – |

The 27 classes are SimObject, SimSet, SimGroup, MaterialPropertyMap, NetObject, NetConnection, GameConnection, SceneObject, GameObject, Camera, TerrainBlock, WaterBlock, Sky, Sun, MirrorSubObject, DynamicGrass, DynamicGrassReplicator, DynamicShapeReplicator, BigDataStartEvent, BigDataChunkEvent, ConnectionMessageEvent, NetStringEvent, RemoteCommandEvent, RequestReloadEvent, GhostAlwaysObjectEvent, TerrainChunkEvent and TerrainRequestUpdatesEvent. None is a datablock class.

The 5.12 function list differs from 5.00r7's by eight non-3D additions (`findplayerbycommunityname`, `getmusicfilename`, `gettileset`, `gettilesettype`, `ismusicplaying`, `issoundplaying`, `switchtoopengl`, `TGraalVar.clearemptyvars`) and one removal (`TDrawableObject.toweapons`).

Every other difference found:

- **Packaging.** 5.00r7 ships the 3D engine as a DLL with five exports that imports its runtime from the 2D engine ([T3D-093](3d-engine-static-reads-2026-11-25.md)); 5.12 links it in.
- **Strings only in 5.00r7** (18 of about 1,990): a terrain-file resave warning and a load message, the IPX and broadcast address formats, the `NetInterface` type name (5.12: `GeneralNetInterface`), and the default move-map bind names (`moveforward`, `moveforward2`, `movebackward`, `movebackward2`, `turnleft`, `turnright`, `pandown`, `mousefire`, `alttrigger`).
- **Only in 5.12:** FFmpeg video capture and streaming prefs and functions, `$pref::Video::resolution` and `fullscreenbitdepth`, `isopengl` / `switchToOpenGL`, FreeType, and `shadowdirection`. None of these adds or removes a 3D net class.
- GameObject field layout was not compared (5.12's live list: [live-512-gameobject-fields](live-512-gameobject-fields-2026-11-25.md)).

**Verdict:** for a protocol-24 server route 5.00r7 and 5.12 look the same: the same protocol and connect checks, the same 27 classes and the same GS2 3D object set. Default 3D key binds may differ. [bin; not run on 5.00r7]

**Correction to [5007-g3d.md](5007-g3d.md):** that note says `CHR_PROTOCOL_LESS` and `CHR_GAME` do not occur in the 5.00r7 3D DLL. This scan finds `CHR_PROTOCOL_LESS`, `CHR_PROTOCOL_GREATER` and `CHR_GAME` present, each referenced from the reject code next to the 24 constant. **[bin]**

## T3D-003: 4.11 is the switch point

| | 4.03r3 | 4.04r2 | 4.11 | 4.20r8 |
| --- | --- | --- | --- | --- |
| Protocol constant | 19 | 19 | 21 | 24 |
| Registered classes | 108 | 108, same names | 30 | 27 |
| Datablock family (SimDataBlock, SimDataBlockEvent, `*Data`) | 28 | 28 | 0 | 0 |
| GameObject | no | no | yes | yes |

- **4.03r3 = 4.04r2** in class set, protocol and file size. They are different builds two months apart; the byte differences are mostly relocated code.
- **4.04r2 → 4.11** drops 79 classes and adds one, GameObject. Dropped:
  - the datablock layer: SimDataBlock, SimDataBlockEvent and all 26 `*Data` classes;
  - the stock game classes that need datablocks: GameBase, ShapeBase, Player, AIPlayer, AIClient, AIConnection, Item, StaticShape, the vehicles (with springs and tires), Projectile, Explosion, Debris, Splash, Lightning, Precipitation, ParticleEmitterNode, PathCamera, AdvancedCamera, Trigger, PhysicalZone, SpawnSphere, WayPoint, Marker, MissionMarker, MissionArea, Path, PathedInterior, InteriorInstance, TSStatic, TSShapeConstructor, Shape3ds, FractalTree, DecalManager, ScopeAlwaysShape, VehicleBlocker, and their events;
  - audio: AudioDescription, AudioProfile, AudioEnvironment, AudioSampleEnvironment, AudioEmitter and the 2D/3D audio events;
  - ScriptObject and ScriptGroup.
- 4.11 keeps the 27-class core plus FileObject, SimpleMessageEvent and SimpleNetObject. 4.20r8 drops those three and raises the protocol to 24.

**Verdict:** 4.11 is the first held build with GameObject and no datablocks, on its own protocol, 21. Its 30 % smaller size is the dropped datablock, game-object and audio classes.

## T3D-004: Linux and Mac against their Windows twins

Static, same day. Class sets here are taken from the compiler's type names for each class's registration template (GCC type-info on Linux and Mac, MSVC RTTI on Windows), checked against plain name strings; the protocol constant comes from the connect-reject code as above. **[bin]**

**Count correction for the Windows sets.** The earlier store scan missed fxSunLight, fxLight, fxLightData, fxFoliageReplicator, fxGrassReplicator, fxShapeReplicator, fxShapeReplicatedStatic, volumeLight and twSurfaceReference. With both sources the Windows sets are 117 (4.03r3 = 4.04r2), 32 (4.11: the old 30 plus fxSunLight and twSurfaceReference) and 28 (4.20r8 = 5.00r7 = 5.12: the 27 above plus fxSunLight). The 4.0x datablock family is 29 with fxLightData.

**Packaging.** Every Linux and Mac build links the 3D engine into the main binary, as Windows 5.12 does. Linux needs fmod (3.70, or 3.75 in 4.20r8), SDL, GL and X11; Mac links only system frameworks.

| Build | Protocol | Classes | Datablock family | GameObject | Against Windows |
| --- | --- | --- | --- | --- | --- |
| Linux 4.03r1 | 19 | 117 | 29 | no | one class swapped (below) |
| Linux 4.04r2 | 19 | 117 | 29 | no | the same swap |
| Mac 4.04r2 | 19 | 117 | 29 | no | the same swap; identical to Linux 4.04r2 |
| Linux 4.10r2 | 21 | 32 | 0 | yes | no Windows 4.10 held; identical to Windows 4.11 |
| Mac 4.10r2 | 21 | 32 | 0 | yes | identical to Windows 4.11 |
| Linux 4.11, Mac 4.11 | 21 | 32 | 0 | yes | identical |
| Linux 4.20r6, Mac 4.20r6 | 24 | 28 | 0 | yes | identical to Windows 4.20r8 |
| Linux 4.20r8 (two builds, 12 and 17 Jan 2007) | 24 | 28 | 0 | yes | identical |
| Mac 5.12 | 24 | 28 | 0 | yes | identical to Windows 5.00r7 / 5.12 |
| Mac 3.04 (extra) | 19 | 188 | 29 | no | the 4.0x set plus 71 GUI, editor and networking classes |

Not held: Linux builds other than these seven (no Linux 5.x), Mac 4.03 and Mac 4.20r8.

**Findings**

- **Linux and Mac 4.0x swap one class against Windows 4.0x.** AIWheeledVehicle is on Linux and Mac only; MissionArea is on Windows only. Protocol and datablock layer are the same. A protocol-19 server that ghosts a MissionArea to a Linux or Mac 4.0x client would hit an unknown class [inf].
- **The switch to GameObject is between 4.04r2 (March 2006) and 4.10r2 (August 2006)**, not at 4.11: 4.10r2 on Linux and Mac already has protocol 21, the 32-class set and no datablocks.
- **4.20r6 already has the 4.20r8 engine:** protocol 24 and the 28-class set. The 21 → 24 change and the drop of FileObject, SimpleMessageEvent, SimpleNetObject and twSurfaceReference happen between 4.11 (September 2006) and 4.20r6 (December 2006).
- **Mislabelled copy:** a lab copy labelled Mac "4.20r6" (`4.20r6-MacOSX`) is byte-identical to the Mac 4.11 build (built 18 September 2006, protocol 21, the 32-class set). The real Mac 4.20r6 is the `4.20r6-MacOSX-PPC` copy.

**Verdict:** for the 3D engine and its wire protocol, Linux 4.20r6 and 4.20r8 can stand in for Windows 4.20r8 in lab runs: protocol 24, the same reject logic and the same 28 classes. Prefer the Linux 4.20r8 built the same day as the Windows 4.20r8 3D DLL. Not compared: the 2D side (login, version string, GS2 function lists), rendering and float behaviour (GCC, SDL, GL), and class ids, which should match because the sets match and Torque numbers classes by sorted name [inf]. The Mac builds are PPC-only, and the lab has no PPC Mac to run them.
