# 5.12 GS2 3D probe on our own server (2026-11-25)

Lab: the real 5.12 client against our own gserver in a lab VM, with a probe
weapon that calls the 3D GS2 functions and objects. The world had a sky, a sun
and shapes but **no TerrainBlock**. Behaviour only. The captures and
screenshots stay in the lab share. Board rows: T3D-016, T3D-019, T3D-021,
T3D-050, T3D-063, T3D-064. **[lab]**

## Entering 3D and events (T3D-021)

- The world draws.
- The weapon receives onGraal3DLoginStep with steps 4, 5 and 6.
- `isGraal3DMode` does not exist in 5.12. `isgraal3d` reads true in 3D.
- A weapon file saved with CRLF line ends is not compiled, so the client runs
  nothing from it. Serve weapon scripts with LF line ends.

## Objects a script makes (T3D-016)

- A script-made GameObject is created and the client fetches its shape, but
  the object never draws.
- Script-made Sky, Sun and WorldEditor objects show nothing.
- So in this test, only ghosted objects from the server draw.

## Terrain (T3D-019, T3D-050)

- `getz` returns 0 everywhere, because the world has no terrain.
- `Terraformer.loadGreyscale` crashes the client (access violation in the 3D
  engine) as soon as the PNG file really exists. This happened with 8-bit
  grey, 24-bit RGB and 32-bit RGBA PNGs, both local and served.
- The terrain lab's follow-up confirms that loadGreyscale needs a ghosted
  TerrainBlock. With one present, 64x64 and 128x128 RGBA images load and
  setTerrain returns 1. A 256x256 RGBA image worked once and crashed once,
  and 512x512 and 256x128 crash. The safe use is a small (128 or less) RGBA
  image with a TerrainBlock (torque/terrain-512.md section 7).

## Sky, fog, sun and view-distance functions (T3D-063)

None of setSkyBandColors, setSkyBandSizes, setFogColors, setSunColors,
lightScene, updateVisibleDistance, syncTimeOfDay or setInteriorRenderMode
changed a single pixel. The ghosted Sky and Sun stayed as they were. The view
was live: a script camera move redrew at once, so the lack of change was not
a frozen frame. Why the calls do nothing (wrong arguments, or no effect on a
ghosted Sky) is left to the static read.

## Local 3D with no server (T3D-064)

`switchToOpenGL` on a 2D server does start the 3D engine and opens its OpenGL
window, and the 2D HUD disappears. But the client never connects anywhere,
has no camera and draws no 3D view. Locally made Sky, Sun and GameObject
objects do not draw. So a client cannot build a 3D world by itself.
