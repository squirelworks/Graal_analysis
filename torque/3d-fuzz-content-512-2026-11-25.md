# 5.12 content fuzzing: `.3ds`, `.dts`, `.dif`, PNG (2026-11-25)

Lab: the real 5.12 client in a VM, served one mutated level file at a time
from our own Seihai gserver (never a third-party server). Each world carried
a single mutated file under a fresh name; runs were unattended with a VM
snapshot restore after any run that lost the client. Behaviour only; crash
addresses, per-run files and screenshots stay in the lab share. Board row:
T3D-038. **[lab][cap]**

The theme across all four formats: a malformed file damages only the one
client that loads it. Nothing reached the gserver or other players in any
case.

## `.3ds`

| Mutation | Result |
| --- | --- |
| Truncated by any amount | Client vanishes — no window, no error box |
| Face count 12 → 65535 | Access violation inside `GRAAL3DENGINE.DLL` |
| First face index 0 → 65534 | Crash inside `opengl32.dll` (a bad index reached the GL driver) |
| Vertex count → 65535 | Drew normally |
| Version → 99 | Drew normally |
| Short face-material sub-chunk | Drew normally |

So the `.3ds` reader does not bound-check the face count or the face index
before handing them on: a large face count faults in the engine itself, and
a large face index is passed through to OpenGL and faults in the driver.
Vertex count, version and a short material sub-chunk are tolerated.

## `.dts`

| Mutation | Result |
| --- | --- |
| Truncated to 30%, or total-size word made huge | Crash (write to a bad or null address) |
| Truncated to 70% | Vanishes silently |
| `start16` → 65535 | Drew nothing; the link held |
| Version → 0 | Drew nothing; the link held |

Consistent with the earlier `.dts` finding that the reader trusts the
version word (`torque/live-512-shapes-2026-11-25.md`): a plausible-looking
but wrong body crashes or draws nothing rather than being rejected. A badly
truncated file or an inflated total-size word crashes; a milder truncation
loses the client silently; `start16`/version out of range draws nothing but
keeps the connection.

## PNG (textures)

| Mutation | Result |
| --- | --- |
| IHDR set to 30000 × 30000 | Crash (huge allocation or a null read) |
| Flipped CRC | Drew wrong or white; no crash |
| 50% truncation | Drew wrong or white; no crash |
| GIF signature on a `.png` | Drew wrong or white; no crash |

The client does **not** check the PNG CRC — a flipped CRC draws without
complaint. Oversized IHDR dimensions crash it (unchecked allocation / null
read). Truncation and a wrong signature degrade the image but do not crash.

## `.dif`

`.dif` never crashed. Truncated to 10%, 50% or 95%, or version set to 0 or
45, the link always held and the client stayed up. Of the four formats the
`.dif` reader is the most robust to malformed input.

## What this means

- The client is the trust boundary: a malformed content file crashes or
  degrades only that one client, never the server or other players.
- Unchecked numeric fields that crash: `.3ds` face count and face index,
  `.dts` truncation / total-size word, PNG IHDR dimensions.
- Tolerated without crashing: `.3ds` vertex count / version / short material
  chunk, `.dts` `start16` / version (draw nothing), PNG CRC / truncation /
  wrong signature (draw wrong), all `.dif` mutations tried.
- A server that serves the real client must therefore produce well-formed
  `.3ds`/`.dts`/PNG; the client will not defend itself against these fields.
