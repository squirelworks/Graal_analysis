# Our "Frankenstein 6.037" is a from-source hybrid: a 6.03r7 Quattro host with the 5.12 proto-24 3D link folded in (T3D-122)

Date: 2026-11-26. Static read (no client/VM run) of our own "Frankenstein 6.037" build (source tree, build docs, a compiled artifact), compared against stock 6.00 (the Quattro 2D engine, [T3D-121](3d-v6-quattro-vs-512-2026-11-26.md)) and 5.12 (protocol 24, [T3D-109](3d-shared-world-subset-2026-11-25.md)). Conceptual only. Board row: [T3D-122](3d-capability-board.tsv).

## Headline

**Our Frankenstein 6.037 is not stock 6.00 and not a patched stock binary — it is our own from-source hybrid** that stitches two of our repro engines into one program: a **6.03r7 Quattro** host half (the native 2D Graal lineage, same as stock 6.00) with the **5.12 Graal3D protocol-24 link** linked directly in. **It gains real proto-24 3D capability that stock 6.00 lacks** — it enters a `"3 "` server, runs the dual-link handshake and login, and receives GameObject/Camera ghosts, control object, sky and terrain over UDP — but **renders only a stand-in box/grid view**, not the real Torque 3D scene (that renderer is future work).

## 1. Identity — what it is made of **[bin]**

A deliberate from-source combination of two of our own repros:

- **Host half:** our repro of the 6.03r7 **Quattro** program — the same native 2D Graal lineage as stock 6.00 ([T3D-121](3d-v6-quattro-vs-512-2026-11-26.md)): session, GS2 weapon scripts, file requests, the 6.x HUD, 1024×768 — carrying the 6.03r7 Windows build token and a window class naming it our Quattro repro.
- **3D half:** our repro of the **5.12 Graal3D engine** — the protocol-24 Torque-style 3D link — linked directly in.

Identity strings: names itself **"Frankenstein 6.0" / 6.037**, 6.03r7 build token, version **0.0.1**; built from one source for macOS/Linux/Windows. **Packing: unpacked** native executable with ordinary C++ symbols for both halves and **no packer markers** (none of the Themida/WinLicense/QPlay/CyaSSL layers that wrap *stock* 6.x, [T3D-121](3d-v6-quattro-vs-512-2026-11-26.md)). Our cross-compile, not a repackaged stock image.

## 2. The "Frankenstein" delta vs stock 6.00 **[bin]**

Stock 6.00 is 2D-only (gen-5 2D protocol, no GameObject, no proto-24, only the inert `GuiGraal3DCtrl` name + `levels3d`/`graal3://` vestiges). Our 6.037 **adds a whole protocol-24 3D networking stack**:

- **Added — the 5.12 proto-24 link.** A `"3 "`-named server (chosen directly or via the Login server's 178 warp, as real 5.12 entered 3D) is entered on **two links at once, exactly as 5.12 did** ([T3D-109](3d-shared-world-subset-2026-11-25.md)): Torque/UDP on the listed port + 1, then TCP login on the listed port. The link is the 5.12 repro's **protocol 24** — handshake, packets/acks, login steps 2–6, events, ghosts.
- **Added — GameObject/Camera ghosting + control object.** Handles **GameObject** and **Camera** ghosts, the **initial control object** and its **movement/movetype**, **sky state**, even **terrain-chunk** reads — none in stock 6.00.
- **Added — a stand-in 3D view.** After login step 6 it draws a placeholder over the 6.x frame (sky fog colour, ground grid, each GameObject as a box, the player's in yellow, the 6.x frame inset); a switch disables it.
- **Bridged — 3D ↔ GS2.** 3D-link server text (weapons/flags/scripts) feeds the 6.x GS2 machine; its triggers go back as events ([T3D-018](3d-client-events-420r6-2026-11-25.md)).
- **Swapped/enabled — UDP.** Stock 6.x's connect path opens no datagram socket; this build **leaves UDP enabled**, the 3D link a UDP socket tied to the TCP login.
- Beyond stock's inert name: stock's `GuiGraal3DCtrl` has no scene graph; ours stands up a (placeholder) 3D view behind the concept.

**Not added (honest gap):** the **real Torque world renderer** — terrain, interiors, DTS/`.3ds` shapes, sky textures — is **not drawn yet**; it *reads* the 3D world but renders only the box view. Also not yet: 3D movement keys, the 6.x start screen/server list, a gserver 3D-mode lab run.

## 3. 3D-capability verdict

**Yes — our Frankenstein 6.037 gains real protocol-24 3D capability that stock 6.00 lacks.** A from-source hybrid folding our 5.12 Graal3D (proto-24) link into a 6.03r7 Quattro host, it genuinely enters a `"3 "` server, runs the proto-24 dual-link handshake and login steps, and receives GameObject/Camera ghosts, control object, sky and terrain over UDP — but renders only a stand-in box/grid view, not the real Torque 3D scene (that renderer is future work). Emphatically **not** "stock 6.00 repacked."

## For a server

Unlike stock 6.00, our Frankenstein 6.037 **can be driven as a 5.12-class proto-24 3D client** — point it at a `"3 "` server and a gserver can run the proto-24 handshake and ghost GameObjects/Camera, control object and movement, sky and terrain over the UDP+TCP dual link, with server text reaching its GS2 machine — but expect only a stand-in box/grid view, not a rendered Torque world, until the real 3D renderer is wired in.
