# Precipitation and Lightning are 4.04r2-only client classes, and our server can't place one (T3D-049, Linux 4.04r2)

Date: 2026-11-25. Registered-class / GS2 `-listscriptfunctions` reads for 4.04r2/4.20r8/5.00r7/5.12 plus a single-client protocol-19 lab on native Linux 4.04r2 (g3d404 route). Observation only. Board row: [T3D-049](3d-capability-board.tsv). Builds on [T3D-081](3d-object-classes-by-build-2026-11-25.md) (the eleven 4.04r2-only classes) and [T3D-106](3d-authoring-surface-2026-11-25.md) (the server's authoring surface); sibling of [T3D-085](3d-particles-512-vs-404r2-2026-11-25.md)/[T3D-084](3d-sound-paths-2026-11-25.md) (particles/audio dropped from 5.12).

## Headline

**Precipitation and Lightning (the stock TGE weather datablock classes) are registered on the 4.04r2 client and gone from the 5.12-class engine** — but **our lab gserver has no path to place one**, so neither draws in a protocol-19 session on this server. The classes exist client-side; the server can't emit them.

## Registered-class evidence **[bin]**

| class | 4.04r2 | 4.20r8 | 5.00r7 | 5.12 |
| --- | --- | --- | --- | --- |
| `Precipitation` | registered | – | – | – |
| `PrecipitationData` | registered | – | – | – |
| `Lightning` | registered | – | – | – |
| `LightningData` | registered | – | – | – |
| `LightningStrikeEvent` | registered | – | – | – |

- All five appear in both the registered-class rep scan and the GS2 dumps on **4.04r2 only**, class rep and name string, absent on the 5.12-class engine (4.20r8 / 5.00r7 / 5.12). Consistent with [T3D-081](3d-object-classes-by-build-2026-11-25.md) (both are among the eleven 4.04r2-only content classes).
- **GS2 members on 4.04r2:**
  - `Lightning (GameBase)` — `strikesperminute - integer`, plus `datablock`/`emitter` refs; strikes automatically at the configured rate.
  - `Precipitation (GameBase)` — `maxmass`, `maxspeed`, `minmass`, `minspeed`, `percentage`, `modifystorm(float, float)`, plus a `datablock` ref.
  - Both are datablock-backed `GameBase` instances — each **requires** its datablock (`LightningData` / `PrecipitationData`) to exist.
- **Not to be confused with the Sky's storm effect**, which is present on **both** builds and is unrelated to these classes: a `weathereffectsenabled` boolean pref and the Sky methods `stormclouds`, `stormcloudsshow`, `stormfog`. Those are cloud/fog on the Sky, not the Precipitation/Lightning particle/strike classes.

## Server emit-path verdict **[srv]**

**The lab gserver cannot author or emit a Precipitation or Lightning into a protocol-19 world — there is no path.**

- The 3D scene-file parser has **no weather keyword** (no precipitation/lightning/storm/rain/snow syntax), confirming [T3D-106](3d-authoring-surface-2026-11-25.md).
- The gserver's protocol-19 datablock set is **only `CameraData` and `PlayerData`** — it does not know `PrecipitationData` / `LightningData`, so it cannot send the datablock a `Precipitation`/`Lightning` ghost needs.
- The protocol-19 ghost set is **Sky + a stock TGE Player/Camera** only ([T3D-106](3d-authoring-surface-2026-11-25.md)); no weather object is ever ghosted.

## Lab: protocol-19 single client **[lab]**

A `weapon3d` GS2 script was delivered to the 4.04r2 session (weapons are sent at mission Phase 1 to **both** protocols, so a GS2 weapon runs on protocol 19).

- **The weapon ran** — a `showtext` overlay "4.04r2 ran t12" updated on its timer. So client-side GS2 executes on 4.04r2, and as a bonus **the 2D GUI overlay draws over the 3D view on protocol 19 too** (as on 5.12, [T3D-058](3d-gui-overlay-420r6-2026-11-25.md)). `weathereffectsenabled = true` ran without error.
- **No Precipitation (rain/snow) and no Lightning (flash) appeared** — the view stayed the plain Sky.
- A `Precipitation`/`Lightning` **could not be instantiated** from the client script: they are datablock-backed `GameBase` objects, and without their datablock (which the server does not send) there is nothing to bind a create to. Per the task, no server weather-emit syntax was added to force a test.

**Verdict: [not reachable on this route].** The weather classes exist on the 4.04r2 client, but nothing on the current server or via a simple client script instantiates or triggers one.

Software GL (llvmpipe): a rain/snow field or a lightning flash would be only weakly verifiable headless at best. Moot here — nothing weather-related drew, so there was no effect to judge.

## For a server

- To actually exercise Precipitation or Lightning on a 4.04r2 (protocol-19) client, the gserver would need **new emit support this lab server lacks**: a world-file weather keyword, a `PrecipitationData`/`LightningData` datablock in its protocol-19 datablock set, and code to ghost the `Precipitation`/`Lightning` object after its datablock loads. That is a server gap to scope separately — not built here.
- **For a 5.12-class client, weather via these classes is impossible** — `Precipitation`/`Lightning` are gone from that engine. The only storm-like effect available on 5.12 is the Sky's `stormclouds`/`stormfog` cloud/fog, which is a different mechanism.

### Second lab confirmation (v2 gserver)

A later run against the **v2 gserver** confirmed the blocker precisely: asking
it to ghost `Precipitation` or `Lightning` logs `no class id or ghost slot`.
The protocol-19 **ghost class table** on that build holds only Camera,
Player, Sky, TerrainBlock and WaterBlock, so the weather objects can't be
ghosted at all — the limit is the fixed object-class table, not the client.
