# What the 3D client does when UDP or TCP drops (T3D-027, Linux 4.20r6)

Date: 2026-11-25. Static read of the Linux 4.20r6 client, then a loopback lab run of the same client against our own 3D lab server, with a small relay between them that could drop UDP or close TCP on command. Linux 4.20r6 is 3D-equal to Windows 4.20r8 ([T3D-004](3d-engines-5007-512-and-403-411-2026-11-25.md#t3d-004-linux-and-mac-against-their-windows-twins)). Runs `udp420-0` to `udp420-d`; no movement input. Board row: [T3D-027](3d-capability-board.tsv).

## Static: the ping and timeout rule **[bin]**

On every tick of the 3D connection the client checks how long it has been since it last sent a ping or received a packet. After **4500 ms** it either sends another ping or, if **8** pings have gone unanswered, times the connection out. A received packet resets the count (as in stock Torque [inf]), so a silent server is timed out about 9 × 4.5 ≈ 40.5 s after its last packet.

| Case | Log line | Dialog |
| --- | --- | --- |
| Timeout | `Connection to server timed out` | `The 3D server connection has timed out` |
| Connect failure | `Connection to the server couldn't be established.` | `The connection to the Graal3D server couldn't be established.` |
| Server drops the link | `Connection with server lost.` | `The Graal3D server has dropped the connection: …` |
| 2D side | – | `You have been disconnected from the game server.` |

## Lab **[lab]**

The 3D world was up by 14.4 s in every run (reference cube drawn), and each change was made at 40 s. At baseline the client sends 2–3 UDP packets a second (a 21-byte update every second and 5-byte packets) and the server 1–2. The TCP game link carries about 2.5 packets a second each way.

| Run | Change | Client reaction | Recovers? |
| --- | --- | --- | --- |
| udp420-a | UDP dropped for 10 s, TCP kept | none visible or logged; it keeps sending one update a second and pings at 4.5 s intervals | **yes, at once and silently** when UDP returns; no new connect |
| udp420-b | UDP dropped for good, TCP kept | 8 pings 4.51 s apart; updates stop after 30 unacknowledged; **times out 40.6 s after the last server packet**, sends a 7-byte disconnect, **closes its own TCP to the gserver**, and returns to the login screen with "The 3D server connection has timed out" | no |
| udp420-c | both TCP legs closed | the server sends a UDP disconnect within 1 ms; the client logs "Connection with server lost.", answers with its own disconnect and returns to login with "The Graal3D server has dropped the connection: You have been disconnected from the game server." | no |
| udp420-d | only the client's TCP leg closed (server's TCP and UDP up) | within about 10 ms the client sends a UDP disconnect and returns to login with "You have been disconnected from the game server." | no |

No run crashed the client, and none made it reconnect by itself (no new TCP connect to the lobby or the gserver, no new Torque connect request).

## For server work

- A UDP outage shorter than about 40 s heals with no action from either side.
- A longer one ends the whole session from the client side, TCP included.
- The 3D link never outlives the TCP link: the client drops 3D at once when its TCP goes away, whatever UDP is doing.
- Clients do not reconnect on their own after any of these.
