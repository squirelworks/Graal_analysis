# The 6.00 and 6.03r7 engines are the "Quattro" 2D lineage, not a 5.12-class 3D client — no GameObject, no protocol-24 (T3D-121)

Date: 2026-11-26. Static read (no client/VM run) of the unpacked Windows 6.00 engine (6.00r2/6.00r4 internals + the recovered 6.00r4 source tree) and of the unpacked original **6.03r7 (v6.037)** Windows client, compared against 5.12 (protocol 24, ~28-class set, [T3D-081](3d-object-classes-by-build-2026-11-25.md)) and 4.04r2 (protocol 19, 117 classes). Conceptual only. Board row: [T3D-121](3d-capability-board.tsv). The packed 6.037/6.113 stubs are a separate matter (`QPlay.exe`/CyaSSL packer listings, not the engine — see `client-internals/skipped-v6-read.md`); cross-era module view in `client-internals/torque-surface-by-era.md`. (Our own from-source "Frankenstein 6.037" repro is a different artifact — [T3D-122](3d-capability-board.tsv).)

## Headline

**The 6.00 Windows engine is NOT a 5.12-class protocol-24 3D client.** It is the native **"Quattro" 2D Graal engine** — classic gen-5 2D protocol, `TServer*`/`TGaniObject`/`TGraalVar` object model — that **never carried** the Torque GameObject + protocol-24 3D class set. It keeps only the shared Graal GS2 shell and the `GuiGraal3DCtrl` **name** (a 2D playfield control, no scene graph behind it) plus inert 3D-mode vestiges.

## 1. 3D networked class set (6.00 vs 5.12 vs 4.04r2) **[bin]**

| class | 4.04r2 (proto 19) | 5.12 (proto 24) | 6.00 (Quattro) |
| --- | --- | --- | --- |
| GameObject (proto-24 control) | absent | **present** | **absent** |
| `TerrainBlock` | present | present | **absent** |
| `WaterBlock` | — | present | **absent** |
| Sky (Torque) | present | present | **absent** (2D sky/gmap instead) |
| Sun / scene light (Torque) | present | present | **absent** |
| Camera control (Torque) | present | present | **absent** (only a 2D pixel/gmap camera) |
| the 11 TGE datablock-content classes (Item/StaticShape/TSStatic/InteriorInstance/Marker/Trigger/PhysicalZone/ParticleEmitterNode/AudioEmitter/Precipitation/Lightning) | **all present** | **all gone** | **all absent** (never carried) |

The whole Torque networked-object layer is absent from 6.00 as names and code: `GameConnection`, `NetConnection`, `SimObject`, `SimGroup`, Torque console/TorqueScript, datablocks, and `.mis`/`.ter`/`.dts`/`.dif`/`.dso`. So none of the proto-24 3D classes (GameObject included) exist. The 11 datablock classes are absent here just as they are gone from 5.12 — but for a **different reason**: 5.12 dropped them from the Torque engine ([T3D-103](3d-dll-deadcode-vs-graal-2026-11-25.md)), while 6.00 was never that engine.

## 2. Protocol marker **[bin]**

**Not protocol 24 — the classic 2D Graal protocol (gen 5).** Tells (no addresses): login is the gen-5 mode-3 frame with the login message on a low PLI id; ordinary game connection to a server named `Login` with the classic server-lister event; the packet-id space is the classic 2D set (low-numbered PLI ids used 2.x→5.x), not a Torque ghost/datablock handshake. No Torque UDP net-connection, no ghost/scope stream, no datablock phase — none of the proto-24 3D mission-start machinery.

## 3. GS2 / Graal surface **[bin]**

- **Present (shared shell):** `TGraalVar`, the GS2 VM + an ActionScript-compatible surface, and the Graal GUI vocabulary including the **`GuiGraal3DCtrl` name** — but in 6.00 it is just a playfield control type (beside `GuiGraalCtrl`) with **no scene graph behind it**; the same name as 5.12's real 3D viewport ([T3D-058](3d-gui-overlay-420r6-2026-11-25.md)), a different thing.
- **Absent (the 5.12 3D GS2 additions):** `TParticleEmitter` ([T3D-085](3d-particles-512-vs-404r2-2026-11-25.md)), and `play2`/`play3d`/`playlooped2` ([T3D-084](3d-sound-paths-2026-11-25.md)). Its particles are a 2D draw pass, not the GS2 class.
- **New in 6.00 but not 3D:** an HTTP layer, RTMP/FFMPEG video, ActionScript/`MovieClip`, a `resolveHost` builtin (6.00r4) — 2D/general features.
- **Inert 3D-mode vestiges:** a `levels3d` folder, a `graal3://` option string, an `onMouseYawPitch` event, and a 3D-terrain-colour builtin survive as strings/folders, but with no live Torque 3D engine behind them (no call site recovered for `graal3://`).

## 4. The original 6.03r7 (v6.037) client — the same lineage, read directly **[bin]**

A static read of the **original 6.03r7 Windows client** (unpacked build, token `G3D0311C`; the staging thread reports this exe is byte-identical to the Wine-lab `graal603.exe`) gives the same verdict as the 6.00 engine, confirming the Quattro lineage carries forward to the shipped v6 line. In v6 there is **no separate `Graal3DEngine.dll`** — 3D, if present, would have to live inside the single client executable (unlike 4.04r2/4.20r8/5.00r7, which load the engine as a DLL). It does not.

- **Zero Torque-3D classes.** None of `GameObject`, `TerrainBlock`, `WaterBlock`, `SimObject`, `SimGroup`, `NetConnection`, `GameConnection`, `SceneObject`, `ShapeBase`, `TSShape`, or Torque `Sky`/`Sun`/`fxSunLight`/`Camera` are present as names or code. No `.dts`/`.dif`/`.ter`/`.mis` content strings, no TorqueScript, no `switchToOpenGL`. The engine names itself **"Quattro"** in the binary.
- **The full 2D Quattro object model is present:** `TGaniObject`/`TGraalAni`, `TLevelObject`, the tile-map set (`TTileMap`/`TTileLayer`/`TTileMapObject`/`TTilesLayer`/`TTileSprite`), the server-side game objects (`TServerLevel`/`NPC`/`Player`/`Weapon`/`Sign`/`Chest`/`Bomb`/`Carry`/`Horse`/`Flying`/`Leap`/`Extra`), a `TSocket` session, FMOD sound (`TSoundPlayerFMOD`), and DirectX9/OpenGL/GDI **2D** rendering (`TWindowDirectX9`/`TWindowOpenGL`/`TWindowGDI`, `TScreenPanel*`, `TPixelBuffer*`) — a pixel/tile pipeline, not a scene graph.
- **GS2 shell intact:** `TGraalVar` with `TScript`/`TScriptMachine`/`TScriptFunction`/`TScriptUniverse` and the var-class family (`TColorVar`, `TTilesVar`, `TStaticVar`, `TActionScriptVar`, `TGraalClientVar`, `TParticleVarModifier`, …) — the same scripting surface, still 2D.

**Deltas from the 6.00 read (both are 2D; neither is a 3D path):**
- The `GuiGraal3DCtrl` **name is gone** in 6.03r7. Of the 6.00 vestiges only the `graal3://` option string and the `levels3d/` folder path survive; the playfield-control name does not. The 3D-mode vestige has **shrunk** by 6.03r7, not grown.
- 6.03r7 **does** carry a 2D particle system — `TParticleEmitter` with `TParticleModifier` and the GS2 `TParticleVarModifier` var class — which the 6.00 read reported absent. These are Graal's own `T`-prefixed 2D classes (not Torque's `ParticleEmitter`/`ParticleEmitterData`): a 2D draw feature added in the v6 line, unrelated to the Torque 3D particle datablock.
- A **Flash/SWF GUI layer** (the `TFlash*` tag/character set) and **RTMP streaming** (`TRTMP*`) are present — the 2D/media features the v6 line added, consistent with the HTTP/RTMP/ActionScript surface noted for 6.00.

So the original 6.03r7 client is a **classic 2D Graal client**: the same answer as 6.00 (no Torque 3D class set, not protocol 24), with the 3D vestige smaller, not larger.

## 5. Verdict

**The 6.00 Windows engine is a different lineage** (the native "Quattro" 2D Graal engine, classic gen-5 2D protocol, `TServer*`/`TGaniObject`/`TGraalVar` object model) that never carried the Torque GameObject + protocol-24 3D class set. It keeps only the shared Graal GS2 shell and the `GuiGraal3DCtrl` playfield-control name plus inert 3D-mode vestiges, with no Torque 3D engine behind them.

## For a server

Neither a 6.00 nor a 6.03r7 Windows client **can be driven as a 5.12-class 3D client**: both speak the classic 2D Graal protocol (gen-5, low-PLI set), not the proto-24 ghost/datablock protocol, and neither has GameObject/Terrain/Sky networked 3D classes to ghost. The "3D" names a v6 client still carries are vestigial, and fewer by 6.03r7 (`levels3d`, `graal3://` survive; the `GuiGraal3DCtrl` name does not). A server treats any v6 client as a 2D client.
