# 3.153 and 4.04r2 on our own 3D server (2026-11-25)

Lab: the real 3.153 (Mac OS X, PPC) and 4.04r2 clients against our own
gserver, each in a lab VM. Behaviour only. The captures, logs and screenshots
stay in the lab share. Board rows: T3D-006, T3D-009, T3D-021, T3D-025,
T3D-041, T3D-054, T3D-067, T3D-089. **[lab][cap]**

## 3.153

**Session.** Our gserver accepts 3.153 on protocol 19 with no special
handling. With a Sky ghosted, the client:

- runs all three stock mission phases;
- takes a stock `Player` as its control object;
- holds the link for about three minutes and quits cleanly.

Without the Sky it crashes. The screen stays on the loading picture the whole
time, so nothing 3D was seen drawn.

**What it requests.**

- It asks for `.dts` shapes and for textures by bare name.
- It asks for sky textures as `.gif`, never `.png`.
- It never asks for `.cs`, `.dso` or `.ter`.
- A TerrainBlock makes it send TerrainRequestUpdatesEvent and ask for
  `heights.info`. So even 3.153 uses Graal's chunked terrain, not a `.ter`
  file. With no terrain on the server it then crashes.

**Server script.** A `.cs` is never fetched, so a server cannot push one. The
marker script never ran. This confirms the static result (T3D-009): 3.153 runs
only its shipped scripts.

**The 12 clientCmd handlers.** All 12 arrive and are dispatched.

| Command | What happens |
|---|---|
| CenterPrint, BottomPrint, SyncClock | call GUI objects that do not exist |
| ChatMessage, ServerMessage | call `onChatMessage` / `onServerMessage`, which do not exist |
| ClearCenterPrint, ClearBottomPrint, MissionStart, MissionEnd | log nothing |
| MissionStartPhase1, 2, 3 | rerun the mission phases and acknowledge each |

An unknown command, `clientCmdT3dProbe`, is dropped silently.

**Startup scripts.** It execs `clientprefs3D.cs` (twice), `keysconfig2D.cs`,
`keysconfig3D.cs` and `languageEnglish.cs`. It writes `.dso` files next to
them.

## 4.04r2

**Session.** The client ran under Wine on Linux; on the Windows 10 VM it
crashes at start. It went through all three phases: datablocks, ghosts and
lighting.

**Events.** The probe weapon sees onGraal3DLoginStep 2, 4 and 5, and
onGhostAlwaysStarted 2.

**Movement.**

- The control object is the stock TGE `Player`.
- The client sends Torque moves only, no position reports.
- The server walked the Player about 19 units, and the server-to-client
  updates changed while keys were held.
- The script `player` object still read the spawn position. So the 2D player
  position does not follow the 3D Player in this setup.

**Drawing.** Only the Sky gradient drew.
