# Windows 4.20r8, 5.00r7 and 5.12: the newly found launcher copies

Date: 2026-11-13. Static read of four owner-held Windows executables found in the client hunt (evidence ID
`CLIENT-HUNT-4X5X-20261113`, [evidence index](../docs/evidence-index.tsv)). Nothing was run. Every finding is **[bin]** unless
tagged otherwise. This is the 4.x/5.x batch of the same hunt as [graal2002-and-140-builds.md](graal2002-and-140-builds.md).

## The short answer

All four executables are the **Delphi launcher** (`Graal4.exe` / `Graal.exe`), not the game. From 4.x on, the game, the
network code, the prop parsers, the packet switches, the GS1/GS2 code and the login token all live in the MSVC engine DLL
(`GraalEngine.dll`), as [v4x-clients.md](../protocol/v4x-clients.md#what-these-clients-are) describes. The engines that
belong with them were found beside them in the owner's collection and compared too (see the next sections).

These builds add **no new prop, packet or token data**: there is no new engine among them. They do settle what the copies are:

| Copy | FileVersion | Size (bytes) | What it is |
|---|---|---|---|
| 4.20r8 "Unpacked" | 4.2.0.8 | 982,528 | The stock 4.20r8 launcher. |
| 4.20r8 "+Packet Logger v2" | 4.2.0.8 | 982,528 | The same launcher with a 20-byte "hacked by" signature string written into padding at the end of the code section. No code changed. |
| 5.00r7 "Unpacked, CRC patch" | 5.0.0.7 | 941,568 | The stock 5.00r7 launcher. |
| 5.12 "untouched v5" | 5.1.2.0 | 941,568 | **Not 5.12 at all.** It is the 5.00r7 launcher with its version resource edited to 5.1.2.0 and a one-byte patch that disables the window-title scan. The engine shipped beside it is the 5.00r7 engine with the CRC patch and two more one-byte patches (below). |

How each column was checked:

- **Engine code absent.** Running the receive-dispatch scanner (`dispscan`) and a jump-table scan for the prop-parser bounds
  (10, 77, 81, 82, 83) over each launcher finds no packet switch and no prop parser, only one unrelated 11-case switch. The GS1
  table scanner finds no command table. The character-immediate token scanner finds no token. Each launcher names
  `GRAALENGINE.DLL` and `GRAAL3DENGINE.DLL` as the modules it loads.
- **Copy against copy.** Byte compares of the two 4.20r8 launchers and of the 5.00r7 and "5.12" launchers, with each differing
  run placed in its PE section.

## The 5.12 "untouched v5" launcher is a re-labelled, cracked 5.00r7 one

Against the 5.00r7 launcher it differs in 63 bytes:

- the version resource (FileVersion 5.0.0.7 → 5.1.2.0, with the resource sizes and the two header fields that hold them);
- **one byte of code**: a conditional jump becomes an unconditional one.

The patched jump sits in the launcher's window-enumeration callback. For each top-level window it reads the title and the
class name, and compares the result with a list of scrambled strings, most likely the window names of known cheat tools **[inf]**. It is a
launcher-side check, separate from the engine's server-driven process scan (S→C 182/183, see
[v5x-clients.md](../protocol/v5x-clients.md)). The stock code skips the compare only when the title is empty. The patched code
always skips, so no window ever matches. The 4.04r2, 4.20r8 and 5.00r7 launchers and the Wine-dumped 5.12 launcher all have the
stock conditional jump at this point. **[bin]**

### Its engine is the 5.00r7 engine, patched

The archive the "untouched v5" launcher came from also holds an engine DLL and the untouched originals as `.bak` files. **[bin]**

- The launcher's `.bak` is the stock 5.00r7 launcher, byte for byte.
- The engine's `.bak` is the stock 5.00r7 engine (the same file as the 5.00r7 folder's unpatched `.bak`), and the engine
  itself has the same link time and size as 5.00r7's.
- The engine differs from the stock 5.00r7 engine in five places. Each one makes a conditional jump unconditional or removes it:
  - Three are the 5.00r7 **"CRC patch"**, the same 8 bytes that turn the 5.00r7 folder's `.bak` into its patched engine.
    Despite the name, they are a **license-file bypass**, not a CRC check. One skips the "The license file(s) have not been
    found." error, one skips "The license file is invalid.", and one drops the rejection of a `license.graal` with fewer
    than five lines.
  - Two are new in this copy, and both turn off **auto-update**:
    - One sits in the handler that raises `onUpdatePackageDownloaded` and `onPackagesDownloadComplete`. It skips the call
      that copies `ExeReplacer.exe` to `ExeReplacer_temp.exe` and restarts the client through it.
    - The other skips the step that applies downloaded `updatepackages/` (`.gupd`) once the package list is complete.
- A "version hack" patcher ships beside it.

The engine imports no version-resource API and compares no FileVersion. The token is assembled in code, not stored as a
string, and none of the five patches touches it. So the edited 5.1.2.0 resource is cosmetic: the copy still logs in as
5.00r7 would. The real effect of the "version hack" is that the server's auto-updater can no longer put back a stock client.
**[bin]**

So the whole "5.12" set is a 5.00r7 install with its license check and auto-update turned off, labelled 5.12. It has no 5.12
code. The archive name ("potentially cracked") was right, and the folder name ("untouched") was wrong.

Any 5.12 work should keep using the 5.12 image dumped under Wine ([v5v6-windows-unpacked.md](../protocol/v5v6-windows-unpacked.md)),
whose launcher is laid out differently from 5.00r7's and is the real 5.12 one.

## The 4.20r8 launchers and the Packet Logger engine

The "Unpacked" archive itself is still password-protected, but an earlier extraction of it was found in the owner's
collection: the stock launcher and the **stock 4.20r8 engine**. The two launchers are the same build. The only difference is
the signature string in padding, which nothing reads.

The stock engine settles the Packet Logger engine's changes for the first time against a real original. Both engines have
the same size and link time. They differ in 290 bytes, all in the code section: **[bin]**

1. **One byte** turns a conditional jump into an unconditional one. This is the signature-check bypass that
   [v4x-clients.md](../protocol/v4x-clients.md#login-server-and-licensegraal) inferred.
2. **Eight bytes** at the end of zlib's `inflate` (its success return) become a jump into the added block.
3. **The added block** in what was zero padding at the end of the code section: the three entry stubs, the loader that
   calls `LoadLibraryA`/`GetProcAddress` at fixed Windows XP kernel32 addresses, and the four DLL and function name strings
   (plus a spare `LogOutgoingPackets` string).

Nothing else changed. So the [Packet logger section](../protocol/v4x-clients.md#packet-logger-third-party-build) is now
complete, and its "[inf]" on the signature bypass becomes [bin]. Everything else the 4.x notes read from the Packet Logger
engine (prop parsers, packet switch, token) is stock 4.20r8 behaviour.

Re-checked today on the Packet Logger engine, with the same results as before:

- the four prop parsers have the case sets in the [4.x prop table](../protocol/v4x-clients.md#prop-parsers) (own and other
  players to 81, NPC to 77, baddy 0–10);
- the receive switch has 99 cases, plus 100 and 108 taken before it.

## What this means for the open 5.x questions

- **App. C.1 row J (5.x prop parsers) is unchanged.** The engine reads behind it ([v5-props.md](../protocol/v5-props.md))
  used the 5.00r7 engine and the Wine-dumped 5.12 engine. The "5.12" copy found here is 5.00r7 code, so it cannot stand in
  for the 5.12 Wine dump, and it adds a third 5.00r7 engine read nothing.
- **5.12 still has no on-disk engine.** The Wine dump stays the only 5.12 code we hold.
