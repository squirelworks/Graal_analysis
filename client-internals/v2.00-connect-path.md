# 2.00: list reply, Connect and the grey window

Date: 2026-10-30. Build: Graal v2.00 (`GNW24011`, md5 `c93e659e2cda36379aaea4706db20b38`). Static reading of the exe, checked against the cross-laptop lab of 2026-10-31 (seihai `documentation/cross-laptop-2026-10-31.md`). Derived facts only; code addresses are left out. Tags as in `protocol/listserver.md`: **[bin]** · **[cap]**.

## The answer

The lab 2.00 run that never reached the gserver was not a list-format problem. The client folder (a copy of the 2.22 distro) had no `objects.dat`. 2.00 checks for it when Start is pressed, sets a fatal flag, and the Connect path later returns early on that flag. The result is a blank grey game window, no socket and no DNS lookup. **[bin]** The lab saw exactly that. **[cap]** The lab listserver and GServer-v2 need no change for 2.00.

## Classes

Delphi RTTI names three socket classes, each with its own VMT: the base `TGraalClient` (parent TObject), the listserver client `TServerListClient` and the game-server client `TAdventureClient`. `TServerListClient` overrides virtual slot 2 (its per-message handler) and slot 3 (an empty `ret`). Slot 0 is the method that closes the socket. **[bin]**

## List reply **[bin]**

- The list client's per-message handler (slot 2) acts on ids 0 and 1 only. Any other id, including the 2 (status), 3 and 5 the lab listserver sends, is ignored.
- Id 0: `GCHAR count`, then per server `GCHAR field count` and that many `GCHAR len + text` fields, each server kept as a string list. The list goes to the server-list form's fill routine, and the handler then closes the list socket through slot 0. The form's row painter draws a row only when it has at least 6 fields, and its detail view needs at least 8.
- Id 1: the same field layout for **one** server, appended to the current list (form field +0x330). If it is then the only row, it is selected. This is an "add one server" message, not a login answer.
- So the lab's single frame (id 0 list, id 2 status) and the earlier two-frame 2.17-style reply are both accepted.

## Connect **[bin]**

1. The Connect button handler needs a non-empty account and password, keeps them, then calls the server-selection routine.
2. The server-selection routine: the selected server must have at least 8 fields. **Field 6 is the host and field 7 is the port**, copied to the host and port globals. Fields 8–15 are optional (two strings and two numbers when there are at least 12, the same again for 16). Then one further setup call and **the game-window setup routine** run, and the game form is shown.
3. The game-window setup routine **returns at once if the global fatal-error flag byte is set.** Otherwise it lays out the game window, then creates `TPlayer`.
4. `TPlayer` constructor: loads `letters.png` and `head26.gif`, does `SetCurrentDirectory(<game dir>levels)`, and when the host global is non-empty creates `TAdventureClient` (step 5).
5. The `TAdventureClient` constructor: if the host or port is empty it shows "The connection could not be established!" without dialling. Otherwise it calls the base class's dial routine: `WSAStartup` once, a host-name cache lookup, `inet_addr`, then `gethostbyname`, `socket`, `TCP_NODELAY`, `connect` to `htons(StrToInt(port))`, non-blocking. Any failure raises, and the same message is shown.

The lab list (name, language, description, url, version, players, ip, port) puts the IP and port where 2.00 reads them.

## The fatal flag

The fatal-error flag byte is set only on a fatal error, right after `Application.MessageBox` and before `Application.Terminate` (which here comes down to `PostQuitMessage`). It is never cleared. The message is "File not found" / "The file X has not been found in the Graal folder!". **[bin]** The sites are in the game-asset loader (`sprites.png`, `pics1.png`, `state.png`, `opps.png`, `bomb1.png`, `bomb2.png`, and `objects.dat` via the object-table loader and its `FileExists` check), plus the `arrays.dat` loader and some quit paths.

The asset loader runs from the main menu's Start handler, before the server list opens. With `objects.dat` missing, the flag is set there. The list window still opens and works, but Connect stops at step 3. In the lab no dialog was seen after Connect. **[cap]** Whether the "objects.dat" box appeared at Start, or was hidden behind the menu, was not recorded.

`head26.gif` was also missing from the lab folder, but `TPlayer` loads it through `TSurfaceOwner` (its load method is VMT slot +8), which has its own exception handler. It is not fatal.

## Lab rule for 2.00

Run 2.00 from a folder that has its own `objects.dat` (the 2.22 distro has none), plus `arrays.dat`, `letters.png`, `sprites.png`, `pics1.png`, `state.png`, `opps.png`, `bomb1.png` and `bomb2.png`. The earlier lab run that reached the gserver used the 2.22 folder plus an `objects.dat` (`decomp-findings-2026-10-24-b/07-lab-findings-46-186-200.md`).

**Confirmed [cap], 2026-10-30:** after `objects.dat` from NewMain 26 (2001-01-15, 33852 bytes) was copied into the same folder, a re-run with the same lab servers showed no dialog at Start or Connect. 2.00 opened TCP to the gserver on 14802, drew the server's start level and chatted. Nothing else in the folder or on the servers changed.
