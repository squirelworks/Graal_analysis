# 2.00: list reply, Connect and the grey window

Date: 2026-10-30. Build: Graal v2.00 (`GNW24011`, md5 `c93e659e2cda36379aaea4706db20b38`). Static reading of the exe, checked against the cross-laptop lab of 2026-10-31 (seihai `documentation/cross-laptop-2026-10-31.md`). Derived facts and addresses only. Tags as in `protocol/listserver.md`: **[bin]** · **[cap]**.

## The answer

The lab 2.00 run that never reached the gserver was not a list-format problem. The client folder (a copy of the 2.22 distro) had no `objects.dat`. 2.00 checks for it when Start is pressed, sets a fatal flag, and the Connect path later returns early on that flag. The result is a blank grey game window, no socket and no DNS lookup. **[bin]** The lab saw exactly that. **[cap]** The lab listserver and GServer-v2 need no change for 2.00.

## Classes

Delphi RTTI, VMT addresses: `TGraalClient` 0x4dabc8 (parent TObject), `TServerListClient` 0x4dac4c, `TAdventureClient` 0x4dacbc. `TServerListClient` overrides virtual slot 2 (0x4db984, the per-message handler) and slot 3 (0x4dbc3c, an empty `ret`). Slot 0 (0x4db160) closes the socket. **[bin]**

## List reply **[bin]**

- 0x4db984 acts on ids 0 and 1 only. Any other id, including the 2 (status), 3 and 5 the lab listserver sends, is ignored.
- Id 0: `GCHAR count`, then per server `GCHAR field count` and that many `GCHAR len + text` fields, each server kept as a string list. The list goes to the list form (0x4a4ffc), and the handler then closes the list socket through slot 0. A row is drawn only with at least 6 fields (0x4a512c), and the detail view needs at least 8 (0x4a5250).
- Id 1: the same field layout for **one** server, appended to the current list (form field +0x330). If it is then the only row, it is selected. This is an "add one server" message, not a login answer.
- So the lab's single frame (id 0 list, id 2 status) and the earlier two-frame 2.17-style reply are both accepted.

## Connect **[bin]**

1. Connect button (0x4a604c): needs non-empty account and password, keeps them, then calls 0x4a61e0.
2. 0x4a61e0: the selected server must have at least 8 fields. **Field 6 is the host and field 7 is the port**, copied to the globals at 0x5397a4 and 0x5397a8. Fields 8–15 are optional (two strings and two numbers when there are at least 12, the same again for 16). Then 0x52a458 and **0x525c0c** run, and the game form is shown (0x44aa60).
3. 0x525c0c: **returns at once if the byte at 0x53a610 is set.** Otherwise it lays out the game window, then creates `TPlayer` (0x50ca0c).
4. `TPlayer` constructor: loads `letters.png` and `head26.gif`, does `SetCurrentDirectory(<game dir>levels)`, and when the host global is non-empty creates `TAdventureClient` (0x4dbc40).
5. 0x4dbc40: if the host or port is empty it shows "The connection could not be established!" without dialling. Otherwise it calls 0x4db17c: `WSAStartup` once, a name cache (0x4dad94), `inet_addr`, then `gethostbyname`, `socket`, `TCP_NODELAY`, `connect` to `htons(StrToInt(port))`, non-blocking. Any failure raises, and the same message is shown.

The lab list (name, language, description, url, version, players, ip, port) puts the IP and port where 2.00 reads them.

## The fatal flag

0x53a610 is set only on a fatal error, right after `Application.MessageBox` and before `Application.Terminate` (0x44da90, which is `PostQuitMessage`). It is never cleared. The message is "File not found" / "The file X has not been found in the Graal folder!". **[bin]** The sites are in the asset loader 0x52525c (`sprites.png`, `pics1.png`, `state.png`, `opps.png`, `bomb1.png`, `bomb2.png`, and `objects.dat` via 0x52d36c → 0x52d3c1 `FileExists`), plus `arrays.dat` (0x52330d) and some quit paths.

0x52525c runs from the main menu's Start handler (0x4a78d0), before the server list opens. With `objects.dat` missing, the flag is set there. The list window still opens and works, but Connect stops at step 3. In the lab no dialog was seen after Connect. **[cap]** Whether the "objects.dat" box appeared at Start, or was hidden behind the menu, was not recorded.

`head26.gif` was also missing from the lab folder, but `TPlayer` loads it through `TSurfaceOwner` (VMT 0x4f3ca0, load at slot +8, 0x4f3d28), which has its own exception handler. It is not fatal.

## Lab rule for 2.00

Run 2.00 from a folder that has its own `objects.dat` (the 2.22 distro has none), plus `arrays.dat`, `letters.png`, `sprites.png`, `pics1.png`, `state.png`, `opps.png`, `bomb1.png` and `bomb2.png`. The earlier lab run that reached the gserver used the 2.22 folder plus an `objects.dat` (`decomp-findings-2026-10-24-b/07-lab-findings-46-186-200.md`).

**Confirmed [cap], 2026-10-30:** after `objects.dat` from NewMain 26 (2001-01-15, 33852 bytes) was copied into the same folder, a re-run with the same lab servers showed no dialog at Start or Connect. 2.00 opened TCP to the gserver on 14802, drew the server's start level and chatted. Nothing else in the folder or on the servers changed.
