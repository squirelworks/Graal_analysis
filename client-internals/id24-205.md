# Id 24 in 2.05: the same weapon-image list

In 2.05, client id 24 already carries the weapon-script image list that the 2.17.1, 2.22 and 2.31 clients send (`decomp-findings-2026-10-25-g/01-id24-image-list.md`). It is not an emote, and it has no other meaning. Read from the 2.05 program.

## What 2.05 sends

- **The images:** the images that the selected weapon's script shows, at indexes 0 to 199. A single image set aside by the client replaces that list when present.
- **Changes only:** the list is compared with the one sent last.
  - An image that is new or has changed is sent as a record.
  - An image that is gone is sent as its index byte followed by an empty name.
- **Record layout:** a record starts with 0x2a plus the image's index. Tag bytes follow (0x20 plus the tag), as in the later builds:
  - tag 0 is the name;
  - tags 1 and 2 are x and y;
  - tag 3 is the layer, sent only when it is not 1;
  - tag 4 is the part, sent only when its width and height are above 0;
  - tag 5 is the colours, sent only when any is not 1.0;
  - tag 6 is the zoom, sent only when it is not 1.0.
- **Full list:** the full list starts with the marker 0x29 (GCHAR 9), as later. It goes out:
  - when nothing has been sent yet and there are images;
  - and when a countdown of 60 runs out. That is every 61st call, against 101 in the later builds.
- **Copies:** the text always goes out as UDP id 15. The TCP copy (id 24) goes out when UDP is off for the client, or when some player in the level is not reached by UDP. This is the same test as 2.17.1 and 2.22.
- **Empty text:** nothing is sent.

## Correction

Earlier notes said 2.05 and earlier use "a four-field form (index, x, y, name)" for this id. That is wrong for 2.05: it uses the tagged form above, with tags 0 to 6. Tags 7 and 8 of the later builds are not sent by 2.05.

## Confirmed, inferred, not tested

- Confirmed from the program: the source of the images, the diff, the record start, the tags and when each is sent, the marker, the countdown, and the UDP/TCP split.
- Inferred: that the countdown runs on the same periodic handler as in the later builds, which would give about 3 s.
- Not tested on a wire. Builds before 2.05 were not read.
